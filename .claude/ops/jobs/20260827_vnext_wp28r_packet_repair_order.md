# WP2.8-R 작업 지시 — 패킷 복구 후 동일 계측기 재probe (2026-08-27, Claude 발행)

전제: WP2.8 판정(`20260827_vnext_wp28_gate_verdict.md`). D 게이트 실패의 원인은 계측기가
아니라 WP2.6 수집 시 17건 fetch 실패로 결손된 동결 패킷이다. 이번 WP는 **입력만 복구**하고
계측기는 한 글자도 바꾸지 않는다. 유료 API 0, merge·ID 발급·Neon/R2 0, 티어 승격 0.

## 절대 금지 (대조 실험의 유효성 조건)

계측기 v2.1의 **프로토콜 문서·관찰 지시문·축 어휘·파생 함수·판정 게이트·임계값·패킷
빌더·렌더러·자산 상한(측당 2장)·블라인드 절차를 일체 변경하지 않는다.** 변경 대상은
결손 자산의 복구뿐이다. 계측기 파일의 SHA가 WP2.8과 동일함을 report에 증명한다.

## Stage A — 결손 진단과 복구

1. WP2.6 패킷의 **실패 17건을 전량 특정**한다(자산 ID, 소속 seed, 좌/우 측,
   실패 원인, 소스). WP2.8 산출물과 대조해 각 seed의 측별 사용 가능 자산 수를 표로 낸다.
2. **네트워크 허용 경로에서** 그 17건만 재fetch한다(WinError 10013 재발 방지 —
   WP2.5는 823건 무실패였으므로 경로 문제다). 재시도·리디렉션 정책은 기존과 동일.
3. 현재 픽셀 드리프트(Architizer 23.6%)는 배제 사유가 아니다. 상태를 기록하고 사용한다.
4. 여전히 실패하는 자산이 있으면 그 사실을 명시하고, 해당 행은 아래 규칙 3으로 처리한다.
5. 복구된 패킷은 **새 버전**으로 만든다(WP2.6 원본 패킷 불변 보존, 양쪽 SHA pin).

## Stage B — 자산 완전성 사전 검증 (신설 상설 규칙)

채점 전에 seed별 측당 사용 가능 자산 수를 검증하고 report에 싣는다.

- 어느 한쪽 자산이 **0인 행은 게이트 채점에서 제외**하고 `excluded_no_assets`로 별도
  보고한다(삭제 금지). 게이트 분모는 자산이 갖춰진 행만으로 계산한다.
- 이 규칙은 이번 WP뿐 아니라 **이후 모든 리뷰 실행에 상설 적용**한다.

## Stage C — 동일 24 seed 재probe

복구된 패킷으로 WP2.8과 동일하게 실행한다. 리뷰어는 무상태 격리이며, 이전 gold·v1·v2·v2.1
결과는 ledger 동결 후에만 공개한다.

## Stage D — 판정 기준 (WP2.8과 **동일**, 변경 금지)

1. D의 `image=same_object` **≥14/15** (Stage B 제외 행이 있으면 분모 조정 후 동일 비율)
2. D의 `scope=same` ≥14/15
3. N100이 `inconclusive`/`unavailable`로 관찰한 seed에서 과반이 비-`same_object`
4. P1 3쌍 중 ≥2쌍 파생 라벨 비-`same`

네 조건 모두 충족해야 PASS. **이번이 마지막 기회다** — 완전 패킷에서도 실패하면 계측기
작업을 종료하고 일괄 승인 티어를 포기한다(대안은 사용자 결정으로 상정).
