## Scale of the problem

- `phash_blocks.json` has **3,230 entries**.
- Multi-source clusters that survived: **4,787**.
- Attempted multi-source joins ≈ 4,787 + 3,230 = **8,017**; the gate vetoed

  duplicate canonical buildings as separate records.

## Hard invariant tripped

> "The gate must not destroy more true positives than false positives."

The gate's defined contract (per `team-reviewer.md` § "After Stage B") is to
break false-positive merges like `bld_026977` (Terrace ≠ Terracotta). It does
that — golden case verified. But empirically it is also breaking true-positive
merges at near-100% rate among the BLOCKs it emits. Precision on surviving
multi-source clusters is high (10/10), but recall has collapsed.

## Most likely root cause

`canonical/match_phash_check.py` `has_phash_overlap`, `threshold = 8`.

Hypotheses (matcher to verify):
1. **Cross-source CDN re-encoding drift.** Divisare uses `images.divisare.com`
   with on-the-fly `c_fit,f_jpg,q_80,w_1200/...` transforms; Archello stores
   on `archello.s3.eu-central-1.amazonaws.com` with its own resize pipeline.
   Even bit-identical input photos can yield phash distances > 8 across
   pipelines (re-quantized DCT coefficients shift several bits). The
   `Hamming ≤ 8` threshold (`~3 %` bit-difference) is calibrated for
   *intra-source* dedup, not cross-source matching.
2. **Different photo selections.** Each editorial source curates its own
   gallery (~3-4 photos per project after `_pick_urls()`'s `[:3]` cap).
   Two sources may genuinely share zero overlapping shots even when both
   document the same building.

Either failure mode makes "zero phash overlap between source A and source B"
a near-useless veto signal between sources.

## Concrete fix options for DB-MATCHER

(Pick one; don't combine until first one is measured.)

1. **Raise cross-source Hamming threshold** to ~16. The 256-bit phash
   tolerates ~6 % bit-difference at threshold 16, which empirically covers
   CDN re-encoding drift. Re-run, re-spot-check 20 blocks; expect false-block
   rate to drop substantially.
2. **Demote the gate from absolute veto → tie-breaker.** Only emit BLOCK
   when (name similarity < threshold) AND (architect similarity < threshold)
   AND (year mismatch) AND (zero phash overlap). The 20-row sample shows
   strong textual agreement (16/20 exact name match, all 20 close architect)
   on every BLOCK — so a textual co-signal would have caught all 20 as
   non-blocks.
3. **Require both sides have ≥ 4 phash hashes** before applying the gate
   (currently `_pick_urls` caps at 4: cover + 3 gallery). With small image
   sets, "no overlap" is the null hypothesis even for genuine matches.
4. **Increase per-row image budget** in `_pick_urls()` from 4 → 10-12. More
   images per side = more chances for a genuine cross-source overlap,
   reducing both fix #2 and #3's pressure.

## What NOT to do

- Don't lower the threshold below 8 (that's already the precision setting).
- Don't drop the gate entirely — golden `bld_026977` correctly stayed split.
- Don't touch `core/vocab.py` (that's not the issue here anyway).
